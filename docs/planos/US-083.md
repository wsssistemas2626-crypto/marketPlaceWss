# Plano — US-083 Seletor de organização e marca no painel

**Story:** US-083 (P) · **Referências:** RF-IAM-15, ADR-013 (consequência: "a marca do tenant aparece depois do
login, dentro do painel").

A story não tem Gherkin no backlog; os cenários abaixo foram escritos a partir do RF-IAM-15.

```gherkin
Cenário: marca do tenant no painel
  Dado que estou no admin com a organização "Loja A" ativa
  Então o cabeçalho mostra o nome, o logo e a cor primária publicados da Loja A

Cenário: troca de organização sem novo login
  Dado que sou membro de "Loja A" e "Loja B"
  Quando escolho "Loja B" no seletor do cabeçalho
  Então o painel passa a mostrar a marca e os dados da Loja B, sem pedir login

Cenário: organização do tipo errado
  Dado que a organização ativa no admin é de vendedor
  Então vejo um aviso para trocar de organização ou abrir o Seller Center (e não um erro genérico)

Cenário: organização sem vínculo
  Dado que a organização ativa não está em identity.org_links
  Então vejo um aviso para escolher outra no seletor
```

## Desenho

| Peça | Onde |
|---|---|
| Caso de uso | `tenancy/application/panel-branding.ts` — tema **publicado** + nome do cadastro como reserva |
| Rotas | `GET /v1/admin/branding` (`@PanelAuth('tenant')`), `GET /v1/seller/branding` (`@PanelAuth('seller')`), ambas `@Requires('org:panel:read')` |
| Permissão nova | `org:panel:read` em todos os 8 papéis (catálogo da US-013) |
| Cabeçalho | `apps/admin/app/cabecalho.tsx`, `apps/seller-center/app/cabecalho.tsx` — marca + `OrganizationSwitcher` + `UserButton` + aviso por código de erro |
| `panelFetch` | devolve também o `code` do Problem Details; o seller center ganhou o seu (`lib/api.ts`) |
| Links entre painéis | `ADMIN_URL`, `SELLER_CENTER_URL` no `.env.example` |

Sem migração nem evento.

## Decisões

1. **`org:panel:read` em vez de reusar `org:sys_memberships:read`.** As permissões de sistema da Clerk não vão
   para o token de sessão, então não servem para `@Requires`. E rota de painel sem `@Requires` é barrada pela
   auditoria da US-013.
2. **Tema publicado, não rascunho**: o painel não muda de cara enquanto o admin experimenta cores.
3. **O seletor fica sempre visível**, inclusive quando a API recusa a organização: é por ele que se sai do
   problema (o caso "WS Sistemas" do dia 23/09 — organização criada à mão, sem vínculo).
4. **Bug herdado corrigido: `org_kind` ausente virava "tenant".** Sem template de sessão na Clerk, o adapter
   supunha `tenant` e o seller center recusava toda organização de vendedor. `organizationKind` passou a ser
   opcional no token: ausente, vale o vínculo do banco; presente e divergente, continua sendo recusado.
5. **Cabeçalho duplicado nos dois apps** (admin e seller center): ainda não existe `packages/ui`. Registrado
   como dívida para quando o pacote de UI nascer.
