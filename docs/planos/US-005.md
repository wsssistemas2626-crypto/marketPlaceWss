# Plano — US-005 [ENABLER] Outbox + Event Bus

**Story:** US-005 · **Referências:** ADR-004, `arquitetura/03-integracoes.md` §2 (envelope CloudEvents),
CLAUDE.md §4.5 (outbox transacional, handlers idempotentes), ADR-014 (armadilhas #3 e #4).

## Peças

| Peça | Onde | Papel |
|---|---|---|
| `packages/contracts` | novo pacote `@mkt/contracts` | envelope CloudEvents em Zod + catálogo versionado de eventos (`registerEvent`/`parseEvent`) |
| `enqueueOutboxEvent` | `platform/src/messaging/outbox.ts` | grava o evento na `<schema>.outbox` usando a **conexão da transação corrente** |
| `createOutboxTableSql` | idem | SQL da tabela de outbox de um módulo (com RLS e grant para o role `platform`) |
| `relayOutboxBatch` | `platform/src/messaging/outbox-relay.ts` | publica pendentes com `FOR UPDATE SKIP LOCKED`; conta tentativas e manda para a DLQ |
| `BullMqEventBus` / `createEventWorker` | `platform/src/messaging/bullmq-event-bus.ts` | fila `events` + `events-dlq`, `family: 0`, 5 tentativas com backoff exponencial |
| `consumeOnce` | `platform/src/messaging/idempotent-consumer.ts` | restaura o TenantContext do envelope e grava `platform.processed_events` na mesma transação do handler |
| `OutboxRelayService` / `EventConsumerService` | `apps/worker` | relay a cada 1 s com o role `platform`; consumidor roteando para os handlers |

## Decisões

1. **O relay é o único lugar (fora de `@PlatformJob`) que usa o role `platform`** com BYPASSRLS: ele
   precisa varrer eventos de todos os tenants. Ele **não** abre TenantContext — quem abre é o consumidor,
   a partir do `tenantid`, para que um handler jamais rode sem tenant.
2. **Idempotência = `event.id` + nome do handler**, gravada na mesma transação do efeito. Se o handler
   falhar, o registro sofre rollback junto e o evento pode ser tentado de novo.
3. **Duas camadas de deduplicação**: `jobId = t:{tenantId}:{eventId}` no BullMQ e `processed_events` no
   banco. A primeira evita trabalho; a segunda é a garantia.
4. **Evento fora do catálogo ou com envelope inválido vai direto para a DLQ** — repetir não vai torná-lo
   válido.

## Testes

| Aceite da story | Teste |
|---|---|
| (1) rollback não publica evento | `outbox.integration.test.ts` → "rollback da transação não publica evento" |
| (2) evento duplicado processado uma vez | idem → "evento duplicado é processado uma só vez" |
| (3) falha 5× vai para DLQ | `event-bus.integration.test.ts` → "falha 5× vai para a DLQ", com Redis real (Testcontainers) e `noeviction` |

Extras: outbox de um tenant invisível para o outro; envelope inválido para a DLQ após esgotar tentativas;
falha do handler permite nova tentativa; contexto de tenant restaurado do envelope; 7 testes de contrato
no `@mkt/contracts`.
