# Plano — US-008 [ENABLER] CI

**Story:** US-008 · **Referências:** ADR-014 §7 ("Wait for CI"), CLAUDE.md §8 (Definition of Done),
RNF-LGPD-04, RNF-TEN-01.

## Workflow (`.github/workflows/ci.yml`)

| Job | O que roda | Por quê |
|---|---|---|
| `qualidade` | `format:check`, `lint` (inclui `lint:boundaries`), `typecheck` | fronteiras entre módulos e tipos são o contrato interno |
| `testes` | `pnpm test` — unit, integração (Testcontainers com as roles de `infra/db/`), RLS, outbox/DLQ e a **suíte de isolamento** da US-074 | é onde o isolamento entre tenants é provado |
| `contrato` | `gen:openapi` + `git diff --exit-code docs/api/openapi.json` | mudar contrato sem atualizar a especificação quebra o build |
| `imagens` | build das 6 imagens Docker (matriz), com cache do GitHub Actions | o deploy da Railway usa exatamente estes Dockerfiles |
| `seguranca` | gitleaks (histórico completo) e `pnpm audit --audit-level high` | segredo vazado e dependência vulnerável não entram |
| `ci` | portão único que exige sucesso de todos | é o status que a proteção de branch e a Railway observam |

## Decisões

1. **Um job-portão chamado `ci`**: a Railway espera um status name estável ("Wait for CI") e a proteção de
   branch fica com uma única checagem obrigatória, em vez de cinco que mudam sempre que a matriz muda.
2. **OpenAPI sem `@nestjs/swagger`**: a versão atual quebra em ESM (`loadPackageSync` não é exportado como
   módulo ES) e, sobretudo, ela pediria decorators de schema duplicando o Zod de `packages/contracts`, que o
   ADR-002 define como fonte da verdade. A especificação é montada a partir dos **metadados dos controllers**
   (`listControllerRoutes`), e a Fase 1 enriquece os schemas a partir dos Zod.
3. **Enumerar rotas pelos metadados do Nest, não pelo router do Express**: o router traz junto middleware
   registrado com `RequestMethod.ALL` (aparece como caminho com os cinco métodos) e o rastro do `exclude` do
   prefixo global. A primeira versão do OpenAPI saiu com 13 caminhos, sendo 5 falsos; com os metadados, os 8
   caminhos reais. A suíte de isolamento passou a usar o mesmo listador.
4. **Dockerfiles entram aqui**, embora o backlog os liste na US-084: sem eles o job `imagens` não teria o que
   construir. A US-084 fica com `railway.json`, variáveis e o runbook de deploy.
5. **`pnpm audit` bloqueia em `high`**. Isso já pegou três avisos altos do `multer` (dependência transitiva do
   `@nestjs/platform-express`), resolvidos com um `pnpm.overrides` para `^2.3.0` — em vez de baixar o nível do
   gate até ele parar de incomodar.

## Verificação feita

- `docker build` da imagem da `api` e da `storefront` localmente: as duas sobem.
- Container do storefront respondendo `GET /api/health` → 200, escutando em `[::]` (armadilha #2).
- `pnpm audit --audit-level high` limpo depois do override.

## Dívida registrada

A imagem da api tem ~874 MB porque copia todo o `node_modules` do workspace podado. Reduzir (com
`pnpm deploy --prod` ou `--filter` de produção) fica para a US-086, junto com o endurecimento.
