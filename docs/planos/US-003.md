## Pacote

`packages/shared-kernel` (`@mkt/shared-kernel`) — puro: sem Nest, sem Drizzle, sem I/O.
É o único pacote que `domain/` de qualquer módulo pode importar (ADR-015 / CLAUDE.md §4.3).

## Decisões de implementação

1. **Centavos como `number` inteiro seguro**, não `bigint`: o `Money` circula em DTOs/JSON e em eventos;
   `Number.isSafeInteger` cobre até ~90 quatrilhões de centavos. Construtor rejeita `float` e `NaN`.
2. **`allocate(weights, remainderTo)`**: distribui o valor pelos pesos, sempre somando exatamente o total;
   os centavos que sobram do arredondamento vão para o índice `remainderTo` (padrão `0`) — no split é a
   plataforma, como manda a RN-FIN-03.
3. **`multiply`/`percentage` usam half-even** (`roundHalfEven`), não `Math.round` (que é half-up e enviesa).
4. **UUID v7 implementado no pacote** (48 bits de timestamp ms + versão + 74 bits aleatórios, RFC 9562):
   o Node ainda não expõe `randomUUID({version: 7})`. O timestamp vem do `Clock`, nunca de `Date.now()`.
5. **`Result` é um tipo de dados simples** (union discriminada), não uma classe: serializa e faz narrowing bem.

## Testes (`test/*.test.ts`) — meta: 100% de cobertura

- `money`: criação a partir de centavos e de string decimal; rejeita float/NaN/moeda divergente;
  soma/subtração; `multiply` com half-even nos empates (0,5 → par); `percentage`;
  **`allocate` soma exatamente o total** em casos com resto (1 centavo entre 3, 100/3, pesos 0);
  comparação e formatação pt-BR.
- `rounding`: tabela de casos half-even (2,5→2; 3,5→4; −2,5→−2).
- `id`: versão/variante corretas, monotonicidade entre dois IDs gerados com clocks diferentes,
  `parse` rejeita UUID v4 e lixo, `timestampOf` devolve o instante usado.
- `result`: ok/err, encadeamento, `unwrap` lançando em `err`.
- `errors`: código e `instanceof`, `details` preservado, serialização sem dados pessoais.
- `clock`: `FixedClock.advance`, `SystemClock` devolve `Date`.
- `domain-event`: `createDomainEvent` exige `tenantId`, usa o `Clock` para `time` e `Id` v7 para o `id`.
